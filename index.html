A three-tier application splits a program into three separate jobs: showing information, applying business rules and storing data, so each job can be built, secured and scaled on its own.

Our 20-minute talk walks through the idea, the parts, one request travelling through them, and the decisions a designer has to make. The running example is a customer pressing Place Order on an online shop.

The three tiers

One job each.
No shortcuts.

The client talks only to the application tier. The database talks only to the application tier. There is never a direct path from browser to database.

01

Client

Job: show

The browser draws the page and collects clicks. It is a thin client: it keeps no business rules and no data, so an update on the server reaches every user at their next click.

  • Web browser
  • HTML
  • CSS
  • JavaScript

Database

Job: store

The database stores the data, runs queries and stored procedures, and keeps everything correct and safe. A transaction saves the order and reduces the stock together, or not at all.
